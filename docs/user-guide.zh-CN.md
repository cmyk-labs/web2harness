## 环境要求与分发状态

桌面发行包尚待发布，目前可使用已有源码目录。本地生成的安装包不代表已正式发布或完成验收。Windows 安装、修复、升级和移除已实现，正式安装器验收单独记录在[发布手册](release.zh-CN.md)中。

| 要求 | 说明 |
| --- | --- |
| ChatGPT 账号 | 在 Web2Harness 浏览器中登录。可用 Web 模型取决于该账号的能力。 |
| Codex 客户端 | 使用可用的 ChatGPT 登录方式，以便请求集成后的模型目录。该会话与启动器浏览器独立。 |
| 网络与本地权限 | 可访问 ChatGPT 和所需 OpenAI 端点，可写入应用数据及所选 Codex 配置。源码安装还需访问依赖仓库。 |
| 源码工具 | Git、Bun **1.4.0**、Node.js **22.12.0 或更高版本**；源码命令流程需要 Codex CLI。 |
| 桌面构建目标 | Windows x64；macOS 13 或更高版本的 arm64 与 x64；Linux x64 与 arm64。构建目标不代表对应安装包已发布或完成交互验收，见[发布目标矩阵](release.zh-CN.md#native-target-matrix)。 |

原生工具不需要隧道、连接器或推理 API key。MCP Bridge 另需隧道、具有 **Tunnels Read + Use** 权限的普通 API key，以及目标 ChatGPT 账号和工作区中的连接器使用权限。

应用路由变更前，先结束受影响 Codex 客户端中的任务。如果其他路由器或包装工具也控制该路由，应确定一个路由管理方；当前不支持多个路由管理程序组合使用。项目数据和工具权限如何跨组件传递，见[架构设计](architecture.zh-CN.md)。

普通用户可以在自己的工作站上安装和使用。开发与回归必须使用隔离 DEV 配置；安装器、更新器和移除流程的验收需要一次性虚拟机或专用测试操作系统，见[隔离测试流程](development.zh-CN.md#standard-isolated-test-procedure)。

## 安装与启动

### 已有源码目录

在仓库根目录执行：

```bash
git --version
bun --version
node --version
codex --version
bun install --frozen-lockfile
bun install --cwd launcher --frozen-lockfile
bun run app
```

安装前核对工具版本。两组依赖均需安装成功；保留首个错误并解决其原因后再继续，不要通过删除锁文件强行安装。启动命令也会在打开桌面界面前检查锁定依赖。

预期结果是启动准备完成，并进入常规 Web2Harness 工作区。该配置可以修改用户的 Codex 集成。如果要修改软件或验证修复，应使用 `bun run dev:launcher`，确认 **Web2Harness DEV** 标识与运行时归属，并按[开发手册](development.zh-CN.md)使用独立 DEV 凭据。

### Windows 安装包

适用于可用发行包或受控验收构建：

1. 获取匹配的安装程序及验证信息，核对版本和架构。源码目录本身不能证明安装包的真实性或签名状态。
2. 结束受影响任务，从目标应用的托盘菜单选择**退出**。仅关闭窗口可能仍在后台运行。
3. 以当前用户身份运行安装程序。Windows 采用无需提权的单用户安装。选择专用应用目录；受保护路径及含无法识别应用文件的目录会被拒绝。
4. 等待**正在准备并校验应用运行组件**完成。安装或恢复期间不要启动 Web2Harness。
5. 打开应用，按下一节完成连接。

应用文件、已验证的私有运行时及安装登记均就绪后，安装器才报告成功。已登记 Windows 安装的正常启动检查就绪状态，不再部署运行时。运行时文件缺失或损坏时，需要通过匹配的安装器修复。

修复时，退出目标应用并重新运行其安装程序。替换过程中会保留恢复信息，失败时尝试回滚。如果恢复也失败，应保留这些信息，并在启动 Web2Harness 前重新运行安装器。不要删除恢复目录或修改归属记录来绕过失败，见[安装恢复](troubleshooting.zh-CN.md#startup-and-installation)。

<a id="first-connection"></a>

## 首次连接 Codex

初次使用时，先选择界面语言。欢迎页会邀请你为[项目仓库](https://github.com/cmyk-labs/web2harness)点亮 Star，这是自愿支持。点击「在 GitHub 上 Star」后，仓库在默认浏览器中打开，返回应用点击「继续配置」即可；也可以直接选择「跳过，开始配置」。应用不验证 Star，也不要求 GitHub 账号。开始配置后，普通重启不会重复显示欢迎页。

浏览器登录、本地配置和 Codex 目录验证是独立检查，应按顺序完成：

1. 打开**连接与模型**，选择**原生工具**及**自动**交互。
2. 选择**打开浏览器**，在其中登录 ChatGPT。其他浏览器的登录状态不会自动转移。
3. 返回**连接与模型**，选择**检查连接**。先处理登录弹窗或浏览器检查失败，再继续。
4. 选择**应用配置**，准备运行时并写入 Codex 集成。仅选中模式不会使其生效。
5. 刷新受影响 Codex 客户端的模型目录。如果仍显示旧目录，结束其任务，完整退出该客户端及其相关后台进程，再保持 Web2Harness 运行并重新打开。
6. 确认启动器显示 Codex 已读取 Web 目录，在 Codex 中选择 **(Web)** 模型及其提供的推理强度。
7. 尝试一个简短只读任务：“列出这个项目的顶层文件，并解释主要入口。”确认回答返回，并在 Codex 中检查实际工具结果。

浏览器检查通过、目标配置生效、目录已验证且任务完成后，连接流程才算完成。后续模型轮次错误应按其所属层面诊断，反复应用已验证的路由不能修复这类错误。

集成生效期间，保持 Web2Harness 运行。原生 Codex 模型也经过配置后的本地路由。如果要在不运行启动器时使用 Codex，请[移除集成](#disconnect-and-uninstall)，并重启受影响的 Codex 客户端。

<a id="daily-use"></a>

## 执行和继续任务

在 Codex 中选择目标项目、**(Web)** 模型及其提供的推理强度，然后正常输入任务。自动交互期间，Web2Harness 将适用上下文发送到 ChatGPT，并将回答返回 Codex。保持任务浏览器页面可用；导航、编辑或关闭页面可能中断轮次。

在 Codex 中处理工具审批。工具仍受当前任务的访问范围、沙箱和审批策略约束。确认实际文件变更和命令输出后，再判断任务是否完成。需要保留历史时，在同一 Codex 任务中继续；不希望携带此前上下文或图片时，新建任务。

主动中断任务时使用 Codex 的任务控件。**运行控制 → 取消活动的 Codex 任务**可能影响所选运行时配置中的多个活动轮次，使用前先确认范围。开发时只控制归属已验证的 DEV 轮次和进程。

| 启动器页面 | 用途 |
| --- | --- |
| **概览** | 查看当前配置、就绪状态及下一项未完成的设置。 |
| **浏览器** | 登录、观察自动执行，或进行手动交接。 |
| **连接与模型** | 检查连接，应用模式和凭据，查看模型或连接器就绪状态。 |
| **偏好设置** | 设置聊天记录、会话复用、窗口行为及可选实验功能。 |
| **用量与诊断** | 查看已观察到的用量、执行诊断、控制运行时轮次并导出安全日志。 |

侧栏语言控件仅更改启动器语言，不更改 ChatGPT 网站语言。**偏好设置**还可控制关闭窗口后后台运行、任务开始时显示浏览器及登录系统时启动。DEV 通过命令显式启动，不提供登录系统时自动启动。

<a id="tool-modes"></a>

## 选择工具模式

工具模式决定请求如何到达 Codex 工具，交互方式决定由谁在浏览器中发送提示词。

| 模式 | 交互方式 | 执行与配置要求 |
| --- | --- | --- |
| **原生工具**，默认 | 自动 | Codex 执行验证后的模型工具请求。需要浏览器登录、连接检查通过、配置已应用及目录已验证。 |
| **MCP Bridge** | 自动 | ChatGPT 连接器经隧道和本地 MCP 服务进入当前 Codex 任务。另需隧道凭据及已验证的连接器绑定。 |
| **MCP Bridge** | 手动，界面标为“零风险” | 操作者发送提示词，MCP 传递任务回答和工具请求。使用独立凭据，由操作者核对远端绑定。 |
| **仅浏览器**，CLI 提供 | 自动 | 返回模型回答，不执行本地工具。需要 CLI 配置和浏览器会话，无需 MCP 隧道。 |

切换模式或交互方式前，先结束活动任务。在**连接与模型**中选择新值，完成所需配置，再选择**应用配置**。成功应用前，以**当前生效配置**为准。应用后按提示刷新目录或重启客户端。手动交互仅适用于 MCP Bridge。

<a id="mcp-bridge"></a>

### 配置自动 MCP Bridge

先准备可用的自动浏览器会话和 Codex 模型目录，并阅读[架构设计](architecture.zh-CN.md)中的远端工具边界。

1. 选择 **MCP Bridge** 和**自动**。必要时先完成**准备模型目录**，并在 Codex 中刷新。
2. 打开**查看凭据设置指南**，创建隧道和具有 **Tunnels Read + Use** 权限的普通密钥，填写 **Tunnel ID** 与 **API key**。该密钥用于隧道认证，不是模型推理密钥。
3. 选择**应用配置**，等待本地隧道连接后再创建远端连接器。
4. 启用 ChatGPT **Developer Mode**。按页面显示的准确名称创建新连接器；常规自动配置使用 **Codex Native2**。选择对应隧道、**Authentication: None** 和 **Allow all actions**。连接器、隧道与密钥必须属于目标账号和 ChatGPT 工作区。
5. 在启动器中选择**验证连接器绑定**，处理未通过项，然后执行一个简短 Codex 任务，检查真实工具结果。

本地隧道运行不能单独证明远端绑定正确，工作区策略也可能限制连接器访问。更换凭据时使用**替换凭据**，应用新值后验证对应绑定。自动与手动交互分别保存连接配置。

DEV MCP 测试还需独立登录、凭据和隧道资源，取得隧道属于 DEV 的明确确认，并验证实际 DEV 连接器绑定。名称不能证明隔离，详见[开发测试流程](development.zh-CN.md#standard-isolated-test-procedure)。

<a id="manual-handoff"></a>

### 执行手动交接

使用独立隧道和密钥，为 MCP Bridge 应用**手动**交互配置。创建页面显示的 **Codex Zero Risk** 连接器，自行确认远端隧道绑定，再运行**检查本地运行环境**。常规与 DEV 配置共用该连接器名称，名称不能证明隔离；本地检查也不会验证远端绑定。

1. 在 Codex 中选择手动 Web 模型条目并启动任务。
2. 出现交接提示后，使用已准备好的剪贴板文本；必要时再次选择**复制提示词**。
3. 在启动器浏览器中选择模型和推理强度，附加 **Codex Zero Risk**，粘贴并发送提示词。如任务带有图片，需自行添加；此模式不会自动传输图片。
4. 只有在 ChatGPT 中发送后，才在启动器中选择**已发送**，等待连接器绑定当前任务。
5. 后续每轮按交接流程继续，并重新确认模型、推理强度和连接器。

此模式下，应用不操作或检查 ChatGPT 页面。浏览器用量检查、自动上下文文件与技能上传、自动**每轮新建**行为均不可用。可选的**手动 Pro 模型**提供更大的声明上下文配置；仅在账号具备所需权限时启用，并在每轮自行选择 Pro。应用无法验证这一选择，更大的预算也不适用于所有推理强度，见[模型参考](reference.zh-CN.md)。

MCP 绑定活动任务且回答返回 Codex 后，交接才算成功。如果持续等待，记录最后完成的交接步骤。“零风险”是模式名称，账号限制和 Codex 工具权限仍然适用。

<a id="conversation-preferences"></a>

## 设置会话与上下文偏好

活动轮次结束后再更改这些设置。保存聊天和复用会话是独立选择。

| 偏好设置 | 默认值与行为 |
| --- | --- |
| **会话复用 → 继续已有聊天** | 默认开启。原生工具或 MCP Bridge 中，符合条件的自动 Sol/Pro 路由保留与已验证 Codex 任务关联的浏览器会话，减少重复发送上下文。上下文压缩会开启新的上下文阶段。 |
| **会话复用 → 每轮新建** | 默认关闭。符合条件的自动 Sol/Pro 路由每轮新建浏览器聊天并重发适用上下文。可处理后续消息丢失连接器的情况，但传输更多且可能更慢。手动交互不生效。 |
| **聊天记录 → 保存到历史** | 新配置默认开启。任务保存到 ChatGPT 历史中，可能应用记忆和自定义指令。升级保留已有配置明确选择的**临时聊天**。 |
| **上下文文件传输（实验性）** | 默认关闭。较大上下文作为文本附件发送，较小上下文内联发送。需要自动交互，不适用于 Luna。 |
| **上下文预算 → 三倍** | 实验功能，默认关闭。启用上下文文件传输后可选，声明更大的上下文与压缩预算。更改后重启受影响 Codex 客户端。不会增加额度，也不保证模型完整利用内容。 |
| **技能作为文件（实验性）** | 默认关闭。自动交互时，将明确选中的 Codex 技能作为命名文本文件上传。其他技能仍通过工具读取；技能和图片共用附件限制。 |

Luna 使用滚动检查点，仅浏览器模式不保留浏览器会话，手动交互遵循操作者交接。它们与 Sol/Pro 保留会话的连续性不同，见[架构设计](architecture.zh-CN.md)。

保存聊天和临时聊天都会将提示词、文件及图片发送到 ChatGPT，关闭历史记录不代表本地处理。任务图片来自 Codex 会话上下文，以前的图片可能再次附加；桥接最多保留最新十张完整图片。如需排除此前图片，应新建 Codex 任务。

浏览器内图片生成不属于受支持的 Web 轮次。Codex 原生 Image Gen 工具使用独立的原生后端路径、认证和额度。卸载 Web2Harness 不会删除已保存在 ChatGPT 的聊天。

<a id="models-and-subagents"></a>

## 切换模型与使用子代理

在**连接与模型 → Web 模型**中查看当前账号的模型 ID 和推理强度，再在 Codex 中选择。账号能力变化后，重新检查浏览器、应用配置并刷新目录。本地能力字段无法解锁账号功能。准确映射和上下文预算集中在[配置与模型参考](reference.zh-CN.md)。

在同一任务中切换 Web 与原生 Codex 模型时，保持 Web2Harness 为路由管理方。其原生路由会转换 Web 检查点并保留原生加密历史，外部路由器可能绕过转换。切换失败时保留任务历史，并使用[路由诊断](troubleshooting.zh-CN.md#codex-routing-and-catalog)。

原生与 Web 模型之间的委派默认使用 **Compatibility V1** 子代理协议。**Native** 保留 Codex 原生协议设置；V2 下，Web 主代理与 Web 子代理通过显式明文标记委派，无法读取的原生加密任务内容会被拒绝。子代理仍遵循各自选择的模型、工具、沙箱和审批规则。

已安装 CLI 时可使用：

```bash
web2harness subagents status
web2harness subagents compatibility-v1
web2harness subagents native
```

`status` 查询设置，另外两个命令修改设置。变更后重启受影响 Codex 客户端并新建任务。可先保守地保持一个活动代理任务。浏览器五标签页上限是本地限制，不代表安全的账号并发额度。ChatGPT 报告账号限制时应停止重试；更多标签页或更大上下文预算不会增加额度。

<a id="diagnostics"></a>

## 查看用量与诊断

**用量与诊断 → 用量**展示本应用在滚动七天内观察到的发送记录，从启用跟踪时开始。其他应用或启用前的活动可能缺失。共享窗口与模型窗口有重叠，不能直接相加；无法归属模型的 Pro 消息单独列出。这不是官方剩余额度或重置时间。手动交互不检查浏览器用量，已有本地记录仍可查看。

出现问题时，运行**用量与诊断 → 健康检查 → 运行诊断**，从最早失败的检查项排查。完成一次有价值的复现后，选择**日志 → 导出安全日志**。无法进入主界面时，使用启动页详情和诊断导出。分享前检查导出内容，并遵循[支持报告清单](troubleshooting.zh-CN.md#support-report)。

<a id="runtime-controls"></a>

## 运行控制

从侧栏「工作区 → 运行控制」进入，查看当前模式、连接就绪状态及观察到的活动状态。该页面分别提供任务控制和集成管理；用量、健康检查和日志仍在「用量与诊断」中查看。

- **取消活动的 Codex 任务**：中止 Web2Harness 正在处理的请求及对应网页任务，保留集成配置。取消操作完成前显示处理中状态，失败时显示错误。
- **移除 Codex 集成**：通过确认对话框解除 Web2Harness 接入并恢复此前的模型路由。活动任务结束后才能执行；需要再次使用 Web 模型时重新应用连接配置。DEV 界面不提供此操作。

活动状态反映浏览器和应用当前观察到的信息，不能证明其他 Codex 客户端没有任务；无法读取时显示未知或不可用。

## 关于项目

侧栏 Web2Harness 名称旁的 GitHub 图标用于打开当前项目仓库。「关于」页面展示标语、功能、版本、操作系统和许可证信息；工作原理图说明 Codex、Web2Harness 与 ChatGPT Web 之间的请求和结果往返，并简述三种工具模式。使用文档、GitHub 仓库及项目许可链接通过系统默认浏览器打开。第三方许可文件继续随仓库和发行包保留，关于页不再提供单独入口。

检测到可用发行版时，更新操作显示在「关于」页面。偏好设置集中管理聊天、窗口和实验功能；连接与运行状态仍在概览和诊断页面查看。

## 更新安装

结束活动任务，记录当前版本、安装方式和模式，将必要配置及诊断证据保留在本地。

| 安装方式 | 更新操作 |
| --- | --- |
| 源码目录 | 关闭目标启动器，在保留本地修改的前提下获取目标版本，安装两组锁定依赖，再运行 `bun run app`。源码运行不启用自动更新。 |
| 桌面安装包 | 有可用发行版时，使用提供的更新操作或匹配的平台安装包，确认替换后正常启动并显示目标版本。 |
| 已登记 Windows 安装包 | 按前述 Windows 安装流程执行。运行时准备属于安装完成条件；失败后尝试恢复不等于更新成功。 |

更新后检查浏览器连接和当前模式，按提示刷新目录，并在敏感任务开始前核对聊天记录设置。正式发布与安装器验收独立于日常使用；开发人员必须使用[发布手册](release.zh-CN.md)要求的隔离环境。

## 断开与卸载

### 保留应用数据并恢复 Codex

1. 结束使用集成的活动任务。
2. 在常规启动器中选择**运行控制 → 移除 Codex 集成**，确认并等待完成。
3. 重启受影响 Codex 客户端，确认恢复后的路由可用，再移除应用文件。

该操作恢复 Web2Harness 接管前记录的路由。如果其他工具修改了路由，恢复操作可能拒绝覆盖，应按[路由故障处理](troubleshooting.zh-CN.md#codex-routing-and-catalog)排查。DEV 不提供生产集成移除功能。

CLI 的 `web2harness route disconnect` 暂时恢复原路由，随后需要重启受影响的 Codex 客户端。启动器会重新连接已安装的集成，因此临时断开不等于永久移除。

### 移除应用并选择数据保留方式

Windows 安装包应先结束任务、从托盘退出，再运行系统卸载程序。卸载程序恢复受管理的 Codex 集成，并提供默认不勾选的**同时删除 Web2Harness 的全部本地数据**选项。

| 选择 | 结果 |
| --- | --- |
| 不勾选 | 本地数据和设置以已断开状态保留，Codex 集成被移除。 |
| 勾选 | 仅移除已验证归属于该安装的数据根目录：设置、启动器浏览器登录、缓存、日志和已安装运行时。Codex 登录、Codex 聊天、项目及无关设置不属于清理范围。 |

如果归属、路由恢复或文件移除无法验证，卸载器报告失败并停止后续删除，处理原因后再重试。源码或其他平台应先移除 Codex 集成，再退出并按原安装方式移除应用。考虑删除数据前，通过[参考手册](reference.zh-CN.md)确认当前数据路径；仅删除程序文件不能证明路由或本地数据已移除。

本地卸载不会删除 ChatGPT 历史，也不会撤销远端连接器、隧道和 API key。不再需要时，在对应账号设置中单独移除。完成后确认 Codex 使用预期路由，且本地数据保留结果符合所选方式。
