## 发布要求与用例目录

发布前由维护者人工复核适用的CAP-001～006、CAP-008～011及Q01～Q17用例。验证新增或受影响行为，保留经复核有效的证据，通过共享流程合并兼容检查。记录约定范围，区分通过、失败、未执行及明确暂缓事项，不因某个清单行合并多项观察就重新开启已完成或已排除的工作。能力验收由人工判断，`bun run verify`及GitHub Actions不自动执行或强制这些用例，不要求固定JSON清单。

| [CAP-002](#cap-002) | 异步 cell 生命周期与等待续接 | 每次发布 | 一个 15 秒任务、运行中的 cell、对同一 cell 的 `wait` 和落盘结果。 |

| Q10 | 崩溃/租约丢失/重启须核实物理状态后回收，不盲目重发未知结果或复活旧队列；隔离故障。 |

| Q13 | 手动模式不自动发送，提交期限从执行阶段开始，界面不承诺强制用户点击间隔；真实手动DEV流程。 |
| Q14 | 普通/最大化/窄窗口中表单、表格、按钮和反馈稳定可用，窄屏溢出仅在表格区域；DEV界面。会话选项跟随状态/搜索且覆盖全部分页，无匹配任务时不列会话，首屏能出现新任务；核对家族/Pro/力度标签及对应模型搜索。 |
| Q15 | 调度和执行参数整体保存；恢复默认仅改草稿，保存时恢复默认来源，包括数值未变的字段。之后明确修改只固定相应字段。重启保留，DEV/生产隔离；配置与DEV检查。 |

| Q17 | 排队/发送/失败/取消关联准确，诊断排除凭据与完整提示；脱敏/导出证据，原生导出遵循CAP-008。 |

<a id="preparation"></a>

## 执行准备

先遵守[标准隔离测试流程](development.zh-CN.md#standard-isolated-test-procedure)：从 `bun run dev:launcher` 启动并核实 DEV 归属，使用独立登录和当前候选源码，通过 `bun run dev:codex` 运行真实 Codex 任务。不得使用模拟器或夹具浏览器代替真实 Web 模型验收。

1. 记录候选版本、提交、未提交差异的标识、实际加载的运行时、Codex 版本、系统/架构、账户计划、Web 模型完整 ID、思考强度及交互/工具模式。先完成生产配置/认证哈希和进程身份基线。
2. 基线用例采用 **Native Tools + Automatic**，明确选择账户实际支持的 Web 模型和强度。子 agent 沿用该模型，不得为通过测试改用原生 API。其他模式、模型和平台按发布范围补测；单组通过不能外推到全部组合。
3. 将 `<TEST_DIR>` 替换为本次新建的独立 DEV 测试目录的绝对路径，允许任务在其中写文件。不要在用户工作目录覆盖现有同名文件。CAP-001 和 CAP-002 串行执行，CAP-002 沿用 CAP-001 的 Codex 会话和目录。
4. 为 CAP-003 准备与候选版本一致的独立 DEV 源码副本，以其绝对路径替换 `<PROJECT_DIR>`，以实际模型 ID 替换 `<WEB_MODEL_ID>`。在新会话中使用只读沙箱，父任务和子任务均不得写入源码、日志或构建产物。测试前记录文件清单、哈希及已有 Git 状态。
5. 只在 CAP-003 内并行运行三个子任务；不要同时启动其他认证验收。外层验收者在被测目录之外记录日志、文件快照和版本结果，不委派只读子任务写工作日志。验收后按隔离流程复核生产边界。

以下提示词可直接复制，先替换其中的路径和模型占位符。工具名称、参数和调用范围以当前 Codex 实际声明为准；顶层工具不一定出现在 exec 的 `tools` 导出中。

## CAP-001：Code Mode 并行读取与原生补丁

原生消息兼容变更需核对：工具前真实正文以 `commentary` 到达 Codex，工具调用与结果保持顺序，最终回答为 `final_answer`；重连回放不重复文字或工具，无效工具块不进入可见答案。压缩策略变更需检查发布阈值、原生压缩与续轮，不裁剪输入，并区分本地 SSE／用量夹具和认证浏览器验收。发送准备变更需覆盖滑块延迟／缺失、显式模型选择不变、准备失败未发送，以及未知发送保持暂停而不重放。子任务失败回执保留原因，不能声称用户取消。

**提示词**

```text
仅在当前测试目录 <TEST_DIR> 操作。先创建 a.txt 和 b.txt，内容分别为 ALPHA 和 BETA。
然后必须通过 Code Mode 的 exec，用 Promise.all 并行调用两个读取文件的工具，将两个结果返回。
再通过 exec 调用 apply_patch 创建 result.txt，内容为 ALPHA-BETA，最后读取验证。
如果没有 exec，请明确报告，不要改用其他方式完成。不要修改测试目录之外的文件。
```

**通过条件与证据**

- 日志中存在真实 Codex `exec` 调用，原始脚本使用 `Promise.all` 发出两个独立读取工具调用；不是一条命令顺序读取，也不是直接返回预期常量。
- 两个实际工具结果分别读到 ALPHA 和 BETA。保存调用 ID、原始工具身份及返回结果，确认两项读取都已完成。
- 后续 `exec` 确实调用 `apply_patch` 创建 `result.txt`，保存补丁事件；仅用 shell 写入或手工补文件不算通过。
- 最后执行真实文件读取或内容断言。文件正文必须为 `ALPHA-BETA`，允许正常末尾换行；核对 a.txt、b.txt 和 result.txt 的实际内容及修改范围。

缺少 exec、未实际并行、工具报错后未完成要求、输出不符或越界写入均不得记为通过。

原生上下文重同步变更应在独立文件任务中增加受控 `codex_context_resync` 回复，在工具调用交付前触发。确认仅一次新会话 `complete` 发送、模型／力度／工具控制不变，之后发生真实原生补丁和命令断言，并在下一轮恢复正常复用。受控故障注入须与自然发生的上下文缺失分别记录。夹具需覆盖图片／文件／技能编码不改写原始输入、真实前缀变化、两次压缩阶段、过期或混合信号、第二次失败明确终止、并行任务隔离，以及 HTTP 重连和主动取消不重复交付工具。还需包含输入已追加桥接进度消息的重连：取消后不得再次发起浏览器提交，新原生轮次仍可正常使用。原始前缀哈希留在内部；附件完整性校验仍须生效。此定向检查不要求重跑无关能力。

回答提取或Markdown一致性变更应在缓冲器和真实DOM夹具中覆盖待提交尾段/中段缺失、空快照、恢复、合法待提交改写及等价包装变化。网页完成但内容覆盖不足时应在有界观察后明确失败，不重发、不返回过期文本。在自有认证DEV任务中区分受控注入与自然故障：核验Codex错误、没有成功交付最终回答、失败页只读及复制提示跟随语言、队列释放和手动关闭。到期、容量回收、取消和禁止失败页续轮由宿主夹具覆盖，再验证真实原生文件操作及同任务续轮。实际序列化诊断仅保留允许的交付方式/标签元数据，正文和凭据仍过滤。复用未受影响的长回答及工具证据。

就绪与待提交格式恢复需覆盖：渲染读取超过两秒探测线、但在原准备截止前返回；始终仅一个未完成读取；到期／取消拒绝及认证检查不变。回放跳过中间帧的流式到最终节点重建，包含尚未写完的加粗／斜体／行内代码及列表标签；确认完整内容按序仅交付一次，而丢字、URL／文件目标变化、已提交段修改仍失败。认证DEV需验证原生压缩及压缩后的实际文件读取命令，最后队列与浏览器占用归零；延迟渲染夹具与自然网页观察分开记录。

另需覆盖待提交段落 → 下划线标题 → 段落的转换，以及未闭合行内代码中的 Windows 路径变为代码元素。保留字面反斜线、标点、链接目标和后续必需段落；仅归一待提交内容的比较，并验证最终观察到的格式只交付一次。复用成功模型／档位证据，复测失败组合时不改变其预算或选择。

原响应改动还需覆盖 UTF-8 跨字节分块、BOM、全部 SSE 换行、v1 继承补丁、输入身份字段后补、长表格／代码／重复段落、隐藏内容排除、错误页面／会话／父链、重复匹配请求、未完成终态、消息结束标记之后且 `[DONE]` 之前的尾部补丁、拒绝 `[DONE]` 后帧、取消及同请求响应体回读。没有回答 DOM 时仍完整交付一次；拒绝时零部分正文交付，不拼接原流与 DOM。未支持的富引用须通过独立 DOM 校验或明确失败。实际输入夹具应覆盖 Enter 被拦截时单次点击提交，证明事件处理结束后正确记录阻止标志，并验证传输终态门禁、有界脱敏网络／异常证据及页面观察器释放。队列故障夹具须跨重连／重启保留阻塞原因、及时失败待发任务、保留手动暂停语义且不重发旧回执。认证 DEV 验证指定模型／强度、原生读取 → 补丁 → 命令证据、续轮／压缩、取消后新任务以及主 agent 加三个真实子 agent，并比较原生等待与 Web 租约时段；未支持／未执行模式单独记录。

## CAP-002：Code Mode 等待与同任务续接

**提示词**

```text
测试 Code Mode 等待续接。仅在当前测试目录 <TEST_DIR> 操作：
在 exec 中执行一个等待 15 秒后返回 WAIT-110-OK 的任务，按照当前 exec 声明设置较短的 yield_time_ms，
让 exec 先返回运行中的 cell_id。然后调用 wait，直到取得结果。
不得重新启动同一个任务，不得在外部另开任务代替等待。
最后将取得的标记通过 apply_patch 写入 wait-result.txt，再读取验证。
如果 exec 或 wait 不可用，请明确报告，不要绕过。
```

**通过条件与证据**

- 原始脚本只启动一次 15 秒任务，yield 小于任务等待时间，例如 1000ms；真实 exec 返回“运行中”及 cell ID，而非直接完成。
- 后续使用 Code Mode 的 `wait` 续接该 cell。允许多次 wait，但 cell ID 必须一致；记录各次调用与最终输出，不得重新提交计时脚本。
- 从完成的任务取得 `WAIT-110-OK`，经真实 `apply_patch` 写入 `wait-result.txt`，回读内容一致，允许正常末尾换行。
- 保存原始脚本、调用时间、运行中返回、cell ID、wait 返回、补丁事件及文件验证；不能用整轮对话耗时推断脚本等待了 15 秒。

如果当前 exec 声明支持 `setTimeout`，可用它实现计时；不得凭顶层 `clock.sleep` 的存在猜测 `tools.clock__sleep` 也可调用。`WAIT-110-OK` 是固定验收标记，不代表被测版本必须为 1.1.0。没有经历运行中 cell 和同 cell 续接的尝试不得记为通过。

## CAP-003：三个真实子 agent 并行只读分析

**提示词**

```text
请实际委派 3 个 Codex 子 agent 并行工作，不要由你扮演三个角色。
项目路径：<PROJECT_DIR>。三个子 agent 均继续使用当前 Web 模型 <WEB_MODEL_ID>，不切换到原生 API。
使用当前 Codex 实际声明或发现的委派工具，不猜测工具名。

子 agent 1：只读调研 GitHub，找一个与当前项目接近的开源项目，实际访问仓库、核对开源许可证，
给出仓库链接、相似点及依据。访问失败要如实报告，不把记忆或搜索摘要当成已访问仓库。
子 agent 2：只读分析当前项目实现了哪些功能，给出源码路径和依据，区分静态实现与运行验证。
子 agent 3：只读分析当前项目有哪些优化点或可新增功能，给出源码依据，区分已有实现与建议，
不得把静态推断表述为已复现故障。

最后由你等待并汇总三者的结果，列出实际子 agent ID 和对应结论，并结束已完成的子任务。
全程只分析，不允许修改或新增任何项目文件，不写工作日志，不运行会产生文件的构建或测试，
不提交或发布，不再创建额外子 agent。若无法完成实际委派、并行执行或 GitHub 访问，明确报告失败环节，
不得模拟成功。保持只读沙箱和正常权限边界。
```

**通过条件与证据**

- 存在三个不同的真实子 agent ID、父子关系及委派事件，执行生命周期有重叠。保留Codex当前调用控制：`parallel_tool_calls=false`时跨模型回合逐次创建，只有工具声明和控制允许时才使用并行批次。先创建全部三个，再等待结果。逐次创建仍可产生并发子任务；完成一个子任务后才创建下一个，或仅描述三个角色，不算并行委派。依据原生任务事件验证并发，不以是否同一HTTP请求或工具批次判断。
- 核对每个子任务实际使用的 Web 模型及只读沙箱，以运行时记录或等效证据确认；仅凭“继承模型”的提示词不能证明没有切换模型。

- 三个子任务都完成，父任务实际取得三份结果并输出汇总。仅成功创建子任务、CLI 退出码为零或子任务自称成功均不够。
- 测试前后项目文件清单、内容哈希、已有修改及未跟踪文件保持一致，并核对文件变更事件；已有修改不得清理。任何项目写入均不通过。

只读检查覆盖父任务和三个子任务。测试报告在外层证据目录保存，不允许为了记录验收而让这些任务写入被测项目。

## CAP-004：模型家族、思考档位与通用预算

适用范围：每次包含自动模式的发布。使用独立登录、可选择 GPT-5.6 Sol 与 GPT-6 且五档均可用的 DEV 账户；缺少账户能力应记为未执行。采用本页准备步骤和任务独占工作区。

   补充验证：窗口只读，标准/三倍选择及恢复默认只改草稿；active HTTP/browser或排队任务存在时拒绝保存，不中断。空闲保存后runtime、preflight、catalog预算一致；旧目录或失败验证不得清除Codex重启提示。32 KiB阈值独立。分别记录通过、失败、未执行并保留历史失败，fixture不替代真实容量或召回验收。

   加载旧96,000/300,000窗口，覆盖user/default/缺失来源并归一到80,000/272,000；保留有效标准/三倍选择，三倍核验240,000/816,000。旧数值/default CLI参数及数值IPC调用须明确拒绝。通过UI和支持的CLI开关验收两档预算，确认没有可编辑窗口字段。配置通过不能替代实际输入容量与召回验收。

缺少模型切换、工具执行或文件证据，或将 5.6 误当成 6，均不通过。普通 GPT-6 消息需独立计数，不进入 Pro 额度计数。 中文 Pro 页面仍显示“停止”时，延迟出现助手节点不能被视为生成停止；整体任务仍受原有截止时间约束。结束后关闭本例拥有的 DEV 页面／任务并核对生产边界，保留证据。

原生工具页收尾变更，应在网页已完成、Codex实际命令仍执行时中断，核对原生Interrupt钩子结果、准确页面释放及后续真实工具调用。验证Windows带空格路径与stdin、源码／制品轻量中断入口一致、原生三秒期限及旧钩子的安全还原。手工调用控制端点只证明释放逻辑，不代表自动钩子交付成功。

4. 在自有夹具中覆盖轮转历史、损坏记录、缺失/不可读来源、超大来源和落盘失败。其余可用记录仍能导出，适用的部分采集、截断和错误必须明确报告；验证启动器日志保留有界且不删除无关文件。补充Responses边界的结构化取消、网络原因及操作/清理同时失败；关联后仍保留错误码和安全原因链，公开响应不得泄露内部调用栈。
5. 检查归档不含凭据/内容哨兵、原始工具内容和浏览器配置，导出不能覆盖应用源数据。记录截图、原生保存结果、归档检查、夹具结果和生产边界对比，保留此前失败。

1. 在独立“运行参数”页验证默认 4／30 分钟／3 秒、恢复默认只改草稿、调度参数保存热应用（窗口变更另走空闲配置事务）、重载持久化和未授权后端拒绝。检查保存/放弃/继续编辑导航、Escape/焦点、非法草稿、保存失败、已保存未应用反馈、重复点击、过期版本和渲染器重启后的草稿恢复。自动展示任务须保留编辑中的设置。覆盖中英文和窄窗口，再检查运行控制筛选、分页、取消及日志关联。
   修改回收／执行参数时，补查标签目标5、空闲30分钟、无进展5分钟、附件2分钟、重试3次及仅手动显示的60／120秒提交默认值。核对可选值、重启后的逐字段user来源、整表单统一修订保存、新请求参数快照、已有保留／重试／手动期限固定、等待工具页保护、执行并发不变、附件分步等待随设置延长且不绕过完成／失败检查、辅助进程兼容及手动压缩外层期限。按影响选择夹具和认证DEV用例，不重跑无关队列流程。
2. 用隔离 HTTP 客户端同时提交 50 个请求，核对共享上限、会话公平、队列数量/字节保护、超时和取消；这些是夹具，不代替认证网页。
3. 用真实 DEV Codex 主代理加三个子代理分别读取自己的独立文件，共四个文件；禁止子代理再创建代理。分别验证原生工具和 MCP Bridge；在 MCP 单名额下，父代理释放网页后子代理仍能完成，父代理必须依据全部真实结果成功交付最终回答。保留工具事件、四份文件结果和调用 ID。文件已执行但随后解析、队列重试或最终回答失败，不能记为通过。
4. 从实际发送日志核对间隔；队列等待不消耗执行超时、不创建页面。调低并发不终止运行任务，取消中的任务在物理清理前继续占名额。
5. 按清单的 `submission_tool` 和 `submission_field` 提交：`parallel_tool_calls=false` 使用单个 `call` 对象，否则使用所公布的 `calls` 批次。单调用 schema 拒绝数组，批量入口保留原有并行调用约束。验证目录和手动连接返回服务端派生的轮次标识/状态：查询及校验失败不关闭轮次，旧回执不关闭新轮次，活动轮次重复连接保持幂等，完成栅栏提交后拒绝连接。验证默认20条分页、查询未命中时仍返回发现入口、精确命名空间查询及schema保持不变。手动模式应排除已知递归桥接方法（包括App前缀别名），保留无关工具。验证无 exec 网关时的两轮发现续接：原生 `tool_search_output` 必须保留新工具的命名空间与 schema，下一轮按精确身份交付该声明工具。验证一次成功提交原子完成批次的校验、登记和封存，返回 `sealed: true`、`execution_state: "not_executed"` 和 `next_action: "end_web_response"`。接受不代表执行：直接结束本轮 Web 回复，不单独调用 `codex_yield_turn`。完成栅栏提交、Web/浏览器物理资源结算及交付意图回执持久化之前，交付和执行仍必须被阻止；回执持久化失败也必须阻止交付。在完成栅栏提交前，以相同 `submission_id` 重试相同批次必须保留批次/调用 ID，结构化参数键序变化不影响幂等性；可选的重复 `codex_yield_turn` 确认也必须幂等。拒绝冲突提交及完成栅栏提交后或取消后的调用；交付前取消必须阻止执行，且物理清理前继续占用名额。验证真实结果进入下一请求，包括审批/拒绝、命名空间、自由格式输入、结构化/错误元数据及多模态结果。错误绑定和未声明工具身份必须拒绝且不执行，纠正时使用本轮准确绑定和目录。保留 Codex 工具选择、并行调用约束、沙箱及审批策略。Zero Risk 仍需用户逐轮确认发送和结束；原子提交不能替代其中任何确认，确认前不得交付，且应用不进行 DOM 自动操作。
6. 注入限流、未知发送、所有者断开和重启，确认暂停或明确失败、回执不复活、无重复发送；恢复必须经明确操作且不能释放仍在执行的页面。
7. 在归属明确的独立运行时夹具中，让多个 CLI 进程及路径别名加入同一规范档案；验证单一所有者、共享容量/发送许可且模型/工具选择不变。不同档案与 Launcher 保持独立。拒绝未认证、错误代次及跨档案传输调用。客户端丢失后保留已占物理资源；所有者丢失不能启动替代执行池。
8. 对照持久化回执检查独立运行时 `browser queue status`，包含所有者离线情况。停止后配置全部三项参数，验证取值、持久化、下次启动生效，以及已有所有者或 Launcher 配置时的拒绝。核实旧运行时及其浏览器停止后，才能执行 `browser queue recover --confirm-browser-stopped`。验证无确认或所有者存活时拒绝、未完成回执记为结果未知的失败、不自动恢复/重放、不能复用仍保留的请求 ID。

9. 自动MCP分别验证工具调用前、真实工具结果后的普通完整回复，无需 `codex_finish_turn`，精确重连不得重新发送。空回复、未完成批次、活动或迟到MCP以及必须调用工具的约束不能被转为成功正文。容量1时记录父代理等待前、重新获准执行后的保留会话身份和真实子结果。在浏览器宿主夹具中覆盖超过5个等待会话、独立缓存上限、普通与等待过期策略及取消/显式关闭；保留页不能增加活动Web并发。Zero Risk保留显式提交回复及用户结束确认。

10. MCP远端恢复变更需覆盖当前/外部绑定、真实工具结果与模型说明的区别、有界流式错误元数据、helper透传、401/403/额度错误排除、实际Retry-After与30/60秒抖动。验证最多两次恢复（或更小配置值）、网页物理释放与无活动绑定原子退休、迟到请求和任何既往活动拒绝恢复、冷却隔离/取消/到期/重启、每个范围单次恢复放行，以及双语窄窗口的本地/远端状态区分。认证DEV保持模型/effort/连接器选择；投递成功时证明真实文件/命令效果，未成功时保留实际远端失败，不记为真实验收通过。

11. 隧道就绪检查变更需覆盖本地探针正常、成功轮询为零以及结构化401/403故障。桌面与CLI均应拒绝就绪，提示修复凭据/权限，并避免使用相同被拒密钥自动重启。指标缺失应保持未知；空闲长轮询下成功时间较旧本身不是故障。更换失效DEV密钥后，分别验证成功轮询和真实命令/文件任务，不与负向检查或夹具结果混记。

分别记录桌面 UI、独立运行时/HTTP/协议夹具、认证原生工具、自动 MCP 与手动/Zero Risk 结果。任何未执行的真实路径不能用其他模式、合成压力测试或历史结果替代。

超时变更需覆盖多个连续操作总耗时超过旧外层上限、但各自仍在[独立阈值](reference.zh-CN.md#independent-operation-timeouts)内的情况。验证附件2／3／5／10分钟设置均不会缩短输入框／卡片等待，压缩各阶段从实际边界开始计时，取消后保持所有权直至清理完成。分别测试helper真实退出／断连与健康的长操作，以及独立隧道探针、逐连接并行WebSocket清理。保留准确模型／强度、权限和单次发送校验。可控时钟与浏览器夹具证明计时行为；认证DEV任务另需提供真实命令结果与完整最终正文证据。夹具、原生Codex／环境失败和已确认的Web2Harness缺陷分开记录。

## CAP-010：HTTP 正文总预算

在当前候选上使用隔离服务/正文夹具，不使用浏览器登录或生产流量。记录配置限制、HTTP 状态、预留/峰值计数及清理证据；结果标为合成测试，不是认证 Web 验收。

1. 验证 Responses 与 compact（包含原生透传）共用 256 MiB 分配估算池，不同服务使用独立池。同时提交 50 个小型待处理正文，不设置 Codex 代理数量上限；再用 50 个大型合成正文耗尽预算，要求 HTTP 503 `request_body_overloaded`、`Retry-After: 1`，且估算预留不超过配置预算。初始预算已满时必须在读取正文前拒绝。
2. 独立于总预算过载检查编码 64 MiB、解码 128 MiB 及 JSON 512 层限制；边界夹具可显式设置测试预算以单独验证各项。覆盖缺失/虚假 Content-Length、密集 JSON、跨块 UTF-8、zstd 膨胀/窗口和串联帧。大小/深度超限返回 413，正文格式错误返回 400 并释放预留。
3. 覆盖等待任务、JSON/SSE 响应、compact 和原生转发。连接断开或终止事件已交付，都不能在适配器实际清理前释放执行预留；取消及解压失败必须结算读取器/解码器资源。全部工作结束后预留归零，新请求可进入。保留原生请求字节及明确的模型/元数据选择。
4. 将 HTTP 分配估算、调度器等待字节及观测到的 RSS 分开记录。256 MiB 估算不是 RSS 硬上限；合成压力测试通过不能证明真实浏览器并发或认证 MCP/手动路径通过。

## CAP-011：原生搜索、内容和传输兼容

适用于影响搜索路由、附件、输出控制、上下文或 Responses 传输的原生工具改动。使用隔离 DEV、已认证账户和明确选择的模型/力度。夹具结果与真实模型/工具验收分别记录，遵守前述准备和收尾边界。

1. 重新应用原生工具配置并重启 DEV Codex，保留 `web_search` 模式、过滤及位置。提示词：“用 Codex 原生联网搜索找一份官方文档，引用来源，再读取 input.txt、补丁写入 result.txt 并通过命令复核，逐项报告真实结果。”确认原生 `web.run` 携原查询/设置到达搜索服务、真实结果回传模型且文件符合预期。关闭搜索或换成浏览器内置联网不能算通过。在转发边界检查 cached/live/过滤，用隔离配置夹具检查原值恢复与用户改动冲突。
2. 按适用范围提供有效内联 PDF/文本/DOCX/XLSX/PPTX 和图片，核对原字节/MIME 到达浏览器且模型识别唯一夹具标识。另测损坏、加密、超限及不支持的引用；解析接受不等于上传/模型通过，本地文件工具属于独立能力。
3. 要求完整 `json_object` 和严格 schema 输出。无效最终正文不得交付成功，纯工具轮次仍可用。有效但不受支持的生成控制须在发送前报错，null/无覆盖值和命令工具预算保持有效；估算用量须标为估算。
4. 检查原始明文 V2 协作、作者／收件方边界及支持的直接调用空加密参数标记。明密混合、原生推理／压缩、加密工具输出及损坏桥接封装须在浏览器工作前失败，不丢历史、改变模型／effort 或重复工具。可见摘要不证明完整导出；正确拒绝只算边界覆盖，不算迁移验收。
5. 检查 HTTP/SSE 与 WebSocket 工具往返，再测具名／默认通道 FIFO、有界跨通道并发、分支／缓存丢失及完整历史恢复。检查授权／账号／组织／项目隔离，WebSocket／预填历史及 HTTP 后代在其他快照刷盘／重启后的纯内存边界；预填不得执行模型／浏览器／工具／下载。自然完成 steering 须覆盖有序接受、自动后继原设置、待处理工具结果／审批、同通道显式续接设置、输入仅应用一次及后继提交前失败。不支持的更早边界不能伪造完成。断连仅影响归属连接，drain／关闭保留清理。不以未有文档契约的 Responses `response.cancel` 帧作为门槛，原生 interrupt 和后台 HTTP 取消另行区分。记录实际传输；合成调度或 HTTP 回退不算认证 WebSocket 通过。
6. 对 URL 引用检查任务／provider／账号精确授权、DNS 前校验、所有地址公网检查、固定 HTTPS／TLS、无环境凭据／代理、重定向独立授权、原字节／MIME、内存／时间上限及取消清理。覆盖普通／工具结果中的 URL、无网络预填、损坏／缺失历史、两模式下 provider 文件 ID 拒绝及原始音视频拒绝。危险目标使用注入网络 fixture，live 仅用授权公开 fixture；预填 ID 不证明下载／模型验收。
7. 当实际 CLI 宣告独立图像生成／编辑工具时，核对真实原生执行器、原图像模型、传入授权、输出字节／事件／产物及任务权限，保持主 Web 模型／effort。通用 hosted 网页／图像／电脑／文件搜索／解释器／MCP 阻碍分别记录；虚构函数、禁用工具、猜端点、新容器或任意原生模型回退均不算等价。Steering 测试中的 hosted 审批结构不证明 hosted 执行。
8. 对可靠性改动注入发送期限后的唯一绑定输入迟到回执：最多一次 Send 激活及一次确认，取消、重复／错配请求和观察丢失保留各自失败／保护状态。远程结果未知仍全局保护，关闭页面不足为证。检查 detach 前仅失败保存的有界私有捕获、隐私投影／撤销、明确缺口、不含正文的普通诊断及仅离线重放；成功／取消不创建产物。保留历史未知原因及原流缺失，故障 fixture 不等于 live 事故已解决。

终态元数据改动须验证：已绑定、唯一、成功结束的 final、end_turn 和两个流结束标记在可选元数据缺失时仍足以证明完成；明确否定的完成值、无效 finish、未结束 final、错误父链／身份及迟到修改仍失败。覆盖输入框可逆 Markdown 序列化，但不得接受内容、链接目标、字面反斜杠或空白变化；覆盖已完成 EOF 工具围栏的完整 JSON／schema 校验，并拒绝截断 JSON 或尾随正文。保留现有来源／DOM 覆盖、取消及就绪用例；不支持的语义事件不得遮蔽后续结束标记或身份／上游失败。

验证同次响应体恢复仅用于正常传输结束，最多一次，不重发、不接受语义失败。在可见正文和工具调用发送处中断原生响应观察者：精确重连须重放一份已校验回复，工具身份稳定且终态唯一，不增加浏览器发送。失败存档与普通诊断轮转分开，测试互斥容量、存档已满诊断、旧证据保留和目录链接边界。重做真实只读分析及三 agent 并行审核，包含主任务最终报告；子任务完成不足以判定通过。

诊断 fixture 还须覆盖实测 `delta_encoding`／`message`／`delta` 事件、隐藏 `model_editable_context` 的仅结构投影、未知／error 不保留，以及分块重放与直接 facts／result 一致且不含已核查私有值。成功样本一致不等于复现 missing-metadata 失败。

已核查未发布候选的限定范围结果（2026-10-18）：真实 CLI resume／interrupt／恢复通过，HTTP 回退为零；公开 PDF URL 读取、独立 prefill 及自然边界 steering 共享组件通过。保留原失败证据，不据此认证远程图片 live、原始媒体、Codex 文件工具端到端或 CAP-011 全部能力。见[已验证范围](native-tools-compatibility.zh-CN.md#evidence)。

同一观察适用时复用 CAP-001～003、CAP-009～010 及有效既有证据。记录工具事件、设置、文件/附件哈希、传输与生命周期结果、生产边界对比及全部未执行/失败路径。详见[能力边界](native-tools-compatibility.zh-CN.md)。

## 新增与维护用例

新增目标能力或改变已有能力时，同步增加或更新对应验收用例，明确夹具与真实路径要求，并在发布前执行。用例编号从 `CAP-012` 继续递增，不因版本变化重编号或复用旧编号。维护中英文相同编号、提示词语义和通过条件，并更新上方目录。

记录新用例的模式/平台/账户适用条件和所需环境，将受影响行为纳入人工验收范围。同一流程的观察覆盖多项要求时复用该流程。真实失败保持可见，维护者的范围或暂缓决定单独记录；退役用例保留编号、原因及替代引用。

新增用例采用以下格式：

```text
编号与名称：CAP-012：<目标能力>
适用范围与复验触发：<模式/平台/账户；受影响依赖>
前置条件：<候选版本、环境、权限、夹具和所选模型>
提示词与步骤：<可复制且不依赖私人路径或旧会话 ID>
通过条件：<可观察、可核验的行为及禁止的替代路径>
必要证据：<工具调用、生命周期、文件/外部结果和边界检查>
共享流程/检查点：<稳定检查点ID、可复用流程及证据引用>
失败与未执行判定：<如何区分，哪些结果不能视为通过>
收尾要求：<只处理本次归属明确的测试资源，保留证据>
```

用例描述保持长期可执行；具体版本是否通过属于版本结果，不写成永久通过结论。
