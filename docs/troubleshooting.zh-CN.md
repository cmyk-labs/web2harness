## 确定故障边界

自动原生工具模式收到网页模型有效的当前轮次重同步信号时，可显示“正在重新同步任务上下文（1/1）”。桥接会在交付工具前，在新会话中完整重发当前 Codex 上下文一次。`context_resync_invalid` 表示控制回复字段／绑定无效或混有其他内容；`context_resync_failed` 表示一次完整恢复后仍无法继续。两者都不代表任务成功，也不属于普通可重试错误。请检查必要附件，按需重新发起请求。模型以自然语言声称前缀哈希不符，不证明原生历史或文件损坏；原始前缀校验只由宿主执行。增大上下文预算或修改 32 KiB 上传触发线不能修复表示差异。

记录应用与 Codex 版本、安装方式、常规或 DEV 配置、当前模式及交互方式、所选模型、失败时间和最终详细错误。“Reconnecting”是中间状态，不能据此确定原因。

响应失败保留具体原因码：`chatgpt_empty_response`表示Web回合结束但没有可用回复或已接受的工具调用；`chatgpt_assistant_turn_missing`表示消息已被接收但未观察到助手回合；`chatgpt_dom_unresponsive`表示同页观察恢复次数已用尽；`chatgpt_response_timeout`表示配置的响应时限已到。这些现象本身不能证明网络故障或Codex执行失败。已接收请求遇到这些错误时不会自动重发，因为原结果可能仍不确定；继续前查看所属会话和关联诊断。

自动MCP模式下，`mcp_handoff_not_received`表示网页已发起携带本轮绑定的连接器调用，但现有完成宽限期结束后，本地broker仍没有任何MCP活动。说明文字不能将这一轮变为正常完成；迟到的真实接收可在同一预算内继续处理，应用不会重发提示词，也不会执行从网页提取的参数。诊断只保留调用／结果计数和绑定匹配事实，不记录参数或绑定值。这是交接未收到的检测，不代表已证实远端安全拒绝或修复远端投递原因。已有本地活动之后的调用，以及不可用／不支持的网页证据，不由这项零活动检查分类。升级此行为后，应一起重启运行时和浏览器辅助进程。

传输诊断最多保留64条事件，优先保留最近的会话请求、响应状态码和完成/失败类别，避免页面静态资源挤掉发送证据。请求句柄达到上限或同页观察重新绑定时，会话计数仍继续记录。HTTP完成本身不能证明存在可见输出或SSE已完成；丢弃事件保留计数。这些记录不含请求URL、请求头或正文。

大上下文渲染与输入框填入是两个阶段。上下文JSON对反引号使用可逆Unicode转义，避免提交后的Markdown链接解析发生异常回溯；解码后的代码、空白和历史标识保持不变。已发送的用户气泡折叠时，回复重新绑定可先展开气泡，核对支持的完整文本结构，再检查是否出现竞争回合。相同前缀或截断气泡不能证明归属。仅分段填入输入框，不能避免最终完整消息触发渲染故障。

对于`tool_identity_mismatch`，诊断将提交身份与当前可见的Codex工具目录对照。匹配到的已声明工具名和布尔状态可区分缺少namespace、把namespace拼入名称、输入格式不匹配等情况；不记录未知提交名称、参数或回复内容。提交被拒绝不代表工具已执行。保留Codex原有工具名称、权限和调用控制。

浏览器smoke测试同样遵守全局Web请求队列和发送间隔。启动器通过操作ID与进程ID确认该测试的helper归属，允许它执行，同时继续用维护锁阻止无关浏览器操作。如果立即提示“busy with browser smoke test”，请保留诊断日志；这是本地归属检查失败，不能据此认定账号或网络限制。

运行**用量与诊断 → 健康检查 → 运行诊断**，保留全部失败项。无法进入工作区时，使用启动页面的**查看详情**和**导出诊断日志**。自动交互按浏览器登录、配置应用、目录就绪的顺序检查；手动交互则需自行验证浏览器及远端连接器绑定。

| 现象 | 排查入口 |
| --- | --- |
| 无法进入工作区、安装失败或移除停止 | [启动与安装](#startup-and-installation) |
| 浏览器可用，但 Codex 没有 Web 模型 | [路由与目录](#codex-routing-and-catalog) |
| 登录、输入框、模型或推理强度检查失败 | [浏览器与账号](#browser-and-account-checks) |

适合重现时，复现一次并立即导出诊断包。出现账号限制或重复的浏览器结构错误后停止重试。对已正常配置的环境反复安装、应用配置，可能掩盖真正的故障。保留浏览器配置、路由日志、检查点及安装恢复记录。

开发工作遵循[隔离测试流程](development.zh-CN.md#standard-isolated-test-procedure)。不要为了复现 DEV 问题而重启、重定向或重新配置生产环境。安装器、更新器和移除验收应在一次性虚拟机或专用测试操作系统中完成。

<a id="startup-and-installation"></a>

## 启动与安装

### 源码启动或依赖安装失败

**检查与处理**：确认在仓库根目录执行，并核对[安装流程](user-guide.zh-CN.md#installation)要求的工具版本。按锁文件安装两组依赖，`bun run app` 也会在启动前检查依赖。保留首个失败命令，处理其报告的网络、权限或依赖问题，不要删除锁文件或更改全局设置来绕过错误。

**恢复判断**：启动页面完成，预期配置环境打开。这只证明桌面启动成功，之后仍需检查浏览器和 Codex 连接。

### Windows 安装失败或恢复未完成

**检查**：保存准确的安装或启动错误。已登记 Windows 安装在安装阶段准备私有运行时，正常启动只检查就绪状态；运行时缺失或损坏需要安装器修复。正式平台验收记录见[发布手册](release.zh-CN.md)。

**处理**：

1. 结束受影响任务，从目标启动器托盘菜单选择**退出**。
2. 收到修复提示时，重新运行匹配的安装程序。自动恢复未完成时，保留恢复文件，并在启动应用前重新运行安装器。
3. 遇到不安全目录、无法识别的文件、重定向路径、文件占用或归属冲突，处理报告中的具体原因。不要删除无关文件、强制关闭全部同名进程或修改安装记录。

**恢复判断**：安装完成，应用可以打开，已有配置可供检查。如果恢复再次失败，收集部署错误和回滚错误。失败事务不能视为安装或修复成功。

### 运行时属于其他实例，或端口被占用

**检查与处理**：通过诊断确认配置环境、进程和端点。无法证明归属时，启动器会拒绝控制运行时。不要终止无关进程来释放端口。DEV 使用其状态命令及独立分配的回环端点，不应复制生产端点或更改全局配置。

如果启动器报告运行时失败后已恢复原 Codex 路由，重启一次受影响 Codex 客户端，再单独修复运行时。

**恢复判断**：目标配置显示自己的运行时及端点已就绪。DEV 控制进程前，按开发流程确认归属。

### 卸载在完成前停止

**检查与处理**：结束任务并退出准确的应用安装实例。卸载器需要验证路由恢复、进程归属及所选数据根目录。路由变更、恢复记录缺失、数据路径重定向或程序文件占用可能阻止移除。处理报告中的原因后重试，保留卸载登记与恢复证据。

**恢复判断**：移除完成，原 Codex 路由可用，本地数据符合保留选择。数据删除复选框默认关闭；保留的数据处于已断开状态，不保留活动的 Codex 集成。Codex 数据和远端 ChatGPT/MCP 资源的范围见[移除说明](user-guide.zh-CN.md#disconnect-and-uninstall)。

<a id="codex-routing-and-catalog"></a>

## Codex 路由与模型目录

### 缺少 Web 模型，或目录始终未验证

**检查与处理**：

1. 确认 Codex 使用 ChatGPT 登录方式。该会话独立于启动器浏览器；API key 或未登录状态可能仅保留内置目录。
2. 自动交互下，先通过**检查连接**，再执行一次**应用配置**。
3. 刷新受影响 Codex 客户端的目录。如果仍显示旧目录，结束其任务，完整退出该客户端及相关后台进程，保持 Web2Harness 运行后重新打开。退出账号、只关闭窗口或新建任务不一定会刷新目录。
4. 查看启动器目录状态并选择 **(Web)** 模型。验证仍失败时，运行诊断并导出新的安全日志。

**恢复判断**：Codex 已读取 Web 目录，启动器标记为已验证。后续轮次失败需单独诊断。开发时只重启归属已验证的 DEV 客户端。

客户端的短超时可能在上游首次连接完成前将它中断。现在仅当完整请求头和查询均相同时，目录GET才共享在途请求，客户端断开后重试也可继续等待该请求。无人等待的请求30秒后取消；无人认领的成功结果最多保留10秒，交付后丢弃；HTTP/传输失败不保留。这不会替换为缓存或伪造的模型元数据，不重试任务执行，也不重启浏览器。客户端断开不会覆盖最后一次已完成的目录健康结果；安全的传输错误码和`http.model_catalog_fetch`操作ID用于区分真实上游失败与重试。持续网络或认证故障仍须按具体原因处理。

### `openai_base_url changed after setup` 或模型“不受支持”

**检查**：其他路由器、包装工具或配置层可能替换了全局路由，或仅替换了单个进程路由。Web2Harness 会拒绝预期外的归属变更。

**处理**：确定一个路由管理方。使用 Web2Harness 时，停用竞争的 provider/proxy 路由，应用 Web2Harness 配置，刷新或重启受影响客户端，并直接启动，不再经竞争包装命令启动。独立 MCP 集成只要不替换路由即可保留。要切换到其他方案，使用**移除 Codex 集成**恢复已记录的原路由，不要手动编辑路由日志。

**恢复判断**：所选路由管理方能够启动目标模型，不再报告归属错误。归属仍不明确时，提交准确错误和安全日志；当前不支持外部路由器组合。

### Web2Harness 退出后原生模型也无法使用

**检查与处理**：集成生效时，原生 Codex 模型也经过本地服务。保持 Web2Harness 运行，或结束任务后使用**运行控制 → 移除 Codex 集成**再退出。恢复后重启受影响 Codex 客户端。CLI 的 `web2harness route disconnect` 仅临时断开，启动器会重新连接已安装集成。DEV 不提供生产集成移除功能。

**恢复判断**：集成运行时原生请求可用，或永久移除并重启客户端后能独立使用。

### 切换模型后出现 `Encrypted content could not be decrypted or parsed`

**检查与处理**：Web2Harness 为原生请求转换 Web 检查点，同时保留原生加密历史。其他路由可能绕过转换。确认只有一个路由管理方，并通过 Web2Harness 复现。保留加密历史和检查点；如果仍失败，记录切换前后模型、是否先发生压缩，并导出新的安全日志。

**恢复判断**：目标模型保留上下文继续任务。仅新任务成功，不能证明原任务已恢复。

### Codex 用量横幅禁用了发送

**检查与处理**：Codex 客户端的发送限制与 Web 模型权限独立。出现 **You're out of Codex and Work usage** 时，恢复该 Codex 账号的发送能力，或使用另一个你拥有、具备权限且没有阻塞横幅的账号。Web2Harness 中仍登录目标 Web 账号。

**恢复判断**：Codex 接受任务，随后正常发出 Web 请求。更换 Codex 登录不会重置或增加 Web 账号额度。

<a id="browser-and-account-checks"></a>

## 浏览器与账号

### 无法完成 ChatGPT 登录

**检查与处理**：在启动器所属浏览器中登录。自动交互的登录验证和会话检查使用临时聊天，与任务历史偏好无关。等待临时聊天输入框可用，验证时不要导航或关闭浏览器。

如果提供 **Try another way**，可用的其他认证方式可能避开平台通行密钥限制。仅支持通行密钥的 macOS 账号存在已知限制，目前没有普遍验证的解决方式。如果没有可用登录方式，记录一次失败，不要反复删除浏览器配置。

**恢复判断**：输入框可用且**检查连接**通过。报告中包含系统、应用版本、账号套餐、登录提供方及输入框是否出现，不包含 Cookie、浏览器存储、认证头或原始配置文件。

### 连接检查无法找到或验证页面控件

**检查**：输入框、发送按钮、推理强度选择器、临时聊天、个性化、模型验证或视口错误，表示尚未建立预期页面状态。

**处理**：

1. 确认使用目标当前版本，按实际情况处理登录、引导、容量或限流提示。
2. 确认能够正常打开临时聊天；即使任务保存到历史，连接检查也使用该页面。
3. 个性化、连接器或模型控件缺失时，明确选择 **ChatGPT Settings → General → Language → English**，重新加载启动器浏览器，再试一次。启动器语言不改变网站标签。
4. 检查时保持启动器可见。如果结构错误重复出现，导出诊断包供实现排查，不要反复重新配置。

**恢复判断**：该账号所需连接检查全部通过。Free 和 Go 流程可能提供 Luna 和 Think 而没有付费推理强度选择器；缺少该选择器不能单独证明登录失败，见[模型参考](reference.zh-CN.md)。

### ChatGPT 暂时限制账号

**检查与处理**：首次收到账号限制后停止重试并等待恢复。五标签页上限是本地边界，不是服务并发额度；更少任务也可能触发限制。应用无法确认剩余额度或重置时间。

减少受影响 Codex 环境中的并发代理工作。对于支持以下设置的客户端，在已有 `[agents]` 表中配置：

```toml
[agents]
max_concurrent_threads_per_session = 1
```

不要重复创建表，也不要同时保留该键与其 `max_threads` 别名。开发测试只修改 DEV 配置。扩大上下文预算不会增加并发能力或额度。

**恢复判断**：账号限制解除后，单个任务能够完成。限制期间反复请求不能提供有价值的恢复证据。

<a id="mcp-bridge-and-manual-interaction"></a>

## MCP Bridge 与手动交互

### 绑定检查失败，或工具始终不可用

原生工具和仅浏览器不需要连接器。MCP Bridge 按以下步骤排查。

**检查与处理**：

1. 确认目标模式及交互方式已经生效，配置已应用。
2. 检查所选配置的 Tunnel ID 及具有 **Tunnels Read + Use** 权限的普通 API key。创建 ChatGPT 连接器前，本地隧道必须已连接。
3. 启用 ChatGPT **Developer Mode**，使用页面显示的准确名称：常规自动交互为 **Codex Native2**，DEV 自动交互为 **Codex Native2 DEV**，手动交互为 **Codex Zero Risk**。共用手动名称不能证明远端隔离。
4. 选择正确隧道、**Authentication: None** 和 **Allow all actions**，确认账号、工作区及相关策略。
5. 自动交互通过**验证连接器绑定**；手动交互自行检查远端绑定，再运行**检查本地运行环境**。后者只证明本地就绪。

当前连接器应作为新身份创建，不要重命名或刷新旧 **Codex Native** 连接器。ChatGPT 可能缓存工具定义。如果更新后的 `codex_exec` 缺少 `sandbox_permissions`、`justification` 和 `prefix_rule`，重新创建当前连接器以加载最新 schema。这些可选字段通过 Codex 请求权限，执行仍由其沙箱和审批决定。

**恢复判断**：真实工具请求进入目标 Codex 任务并返回结果。本地隧道正常不足以证明完成；DEV 验收还需明确确认 DEV 隧道，并验证其实际连接器绑定。

### ChatGPT 报告 `Error creating connector`

**检查与处理**：确认隧道与密钥属于目标账号，本地运行时已连接。即使隧道运行，首次创建也可能失败；检查就绪状态后重试一次。如果再次失败，停止并核对账号、Tunnel ID、运行中的隧道和工作区策略。

**恢复判断**：连接器创建成功，并通过对应自动或手动绑定检查。创建成功本身不代表绑定正确。

### 后续消息的工具消失

**检查与处理**：在现有 ChatGPT 标签页中检查实际连接器；模型自称没有工具不足以构成证据。ChatGPT 可能未在下一条消息保留连接器。当前轮次结束后，在自动交互下选择**偏好设置 → 会话复用 → 每轮新建**再试。这会继续同一 Codex 任务，但使用新的浏览器聊天并重发更多上下文。

必要时使用正确隧道和权限重新创建 **Codex Native2**，再验证绑定。不要通过关闭活动浏览器标签页跳过恢复流程。

**恢复判断**：后续请求返回真实工具结果。如果新聊天也缺少工具，单独报告并附上观察到的浏览器状态及安全日志。

### 手动交接持续等待

**检查与处理**：确认先在 ChatGPT 发送消息，再选择启动器中的**已发送**，且消息附加了 **Codex Zero Risk**。核对网站模型、推理强度和独立手动隧道配置，应用无法检查这些选择。记录最后完成的步骤：复制、粘贴、发送、**已发送**或首次 MCP 调用，参照[交接流程](user-guide.zh-CN.md#manual-handoff)。

**恢复判断**：连接器绑定活动任务，回答返回 Codex。本地运行时就绪不能证明交接已完成。

### Windows 报告 `unable to verify the first certificate`

**检查**：用 Windows `curl.exe` 测试受影响主机，例如：

```powershell
curl.exe -Iv https://api.openai.com/
```

如果该程序使用 Schannel 并收到 HTTP 响应，说明 Windows 信任被测连接。该结果不能证明其他主机也受信任。

**处理**：结束任务并退出目标启动器，仅在启动它的 PowerShell 会话中启用系统 CA：

```powershell
$env:NODE_USE_SYSTEM_CA = "1"
bun run app
```

开发时在该会话使用 `bun run dev:launcher`。安装包则在同一会话启动其准确可执行文件，替代 `bun run app`。重试一次**应用配置**。不要使用 `NODE_TLS_REJECT_UNAUTHORIZED=0` 关闭证书验证，也不要为测试修改机器级信任设置。

**恢复判断**：保持证书验证开启时，受影响连接成功。如仍失败，保留准确的主机错误并导出诊断包。

### 自动审批审查器阻止工具

**检查与处理**：查看明确的审查错误。Codex 审查器可能独立使用原生模型，因此即使选择 Web 模型，原生额度故障也可能导致工具请求被拒绝。恢复审查器可用性，或使用该 Codex 环境明确支持的审批策略。Web 回答成功不构成绕过拒绝的授权。

**恢复判断**：工具获得所需审批，并在 Codex 沙箱内执行。模型声称成功不能替代执行证据。

<a id="task-execution-and-context"></a>

## 任务与上下文

原生工具模式将真实工具前正文按 Codex `commentary` 转发，最终回答按 `final_answer` 转发；传输约定要求将当前 Codex 任务需要的过程说明保留在工具调用块之外，公开过程消息沿用现有事件通道。工具块解析和回答完整性检查仍然生效，模型没有生成进度时，桥接不会编造。子任务原始失败原因、全局发送暂停与用户取消分别保留，不混为一类。

发送前，浏览器等待可用的推理力度滑块，并验证所选模型。完整模型菜单复核有独立的准备期限，不占用发送确认预算；激活前失败属于未发送。`chatgpt_submission_ambiguous` 和 `send_outcome_unknown` 表示尚不能确定是否已接受：明确重试前，请检查该任务页及已完成的工具结果。单独的 HTTP 成功状态或超时都不能授权自动重发。

### 消息发送前的页面准备失败

`chatgpt_composer_unavailable`、`chatgpt_page_structure_unsupported` 和 `chatgpt_preparation_timeout` 表示浏览器准备故障，不代表模型容量不足。登录、会话过期和浏览器验证提示分别保留具体错误。通用服务不可用或 HTTP 503 本身不能证明模型过载。

一次两秒就绪探测超时不代表页面准备预算耗尽。桥接在原准备截止时间内继续等待同一次DOM读取，不叠加就绪探测，也不重发请求；接纳就绪输入框前再次检查取消、截止时间和认证状态。读取被拒绝时保留原始异常；就绪等待到期时，如已有观察超时，会将其保留在cause中。

`chatgpt_browser_unresponsive` 表示任务独占页面在准备或输入截止后，经过额外五秒清理宽限仍未结束操作。应用只关闭该任务页，确认实际关闭后报告失败，不重发消息；其他任务页和登录主页保留。若无法确认关闭，诊断会报告清理失败。核对该任务的工具执行结果后再重试；渲染进程卡住本身不能证明网络故障。

输入连接器查询或准备不带连接器的提示词前，桥接通过原生编辑器删除操作清空其所属草稿，并确认没有残留文字或已选连接器；网页替换编辑器后会重新检查当前输入框。已有连接器经过核验且草稿为空时可以复用。`prompt_attachment_integrity` 表示清空或文字完整性验证失败，桥接会在发送该提示词前停止。取消后仍有独立且有界的清理流程。这不会增加请求重试次数，也不会替换保留会话。

自动交互的新会话最多恢复一次，使用从首次 Web 调度开始计算的同一份 90 秒预算。导航、观察、恢复及后续排队共用截止时间。失败页面释放后，恢复操作重新进入全局队列。预算绑定原生回合身份，HTTP 重连不会重置；通用 retryable 错误也不会额外授予页面恢复。已有会话不会因此被替换为新聊天。

恢复需要独立证明提交尚未开始：无 Send 激活、会话请求、用户／助手回合、Stop 状态或 MCP 活动。仅有 `prepared` 标签不足以授权恢复。已接受或接收状态不明的提交保留原有防重放规则。发送前重新核验模型、effort 和连接器选择。

准备仍失败时，检查准确错误和该任务的 ChatGPT 页面。诊断记录有界的页面／传输类别；CDP 流观察可用时，还记录响应事件数量和可见正文长度，不保存响应正文、工具参数或隐藏推理。流不可读取或被截断时仍标为证据不足；模型说“安全检查阻止”不构成平台拒绝证明。网页自身断网轮询与这份准备预算分开。

### `Reconnecting`、`stream disconnected`、`ChatGPT failed` 或 HTTP 502

**检查**：查看重连后的最终详细错误。这些消息可能来自账号限制、网站错误、控件变化、浏览器页面关闭、路由冲突或 MCP 工具时限到期。通用 502 不能定位为隧道问题。

**处理**：没有账号限制或其他停止条件时，在新 Codex 任务中尝试一次。记录工具是否执行、ChatGPT 是否显示最终回答、新任务是否成功，随后立即运行诊断并导出诊断包。对于 `codex_tool_timeout`，重试前检查实际工具及其绑定轮次的时限。

**恢复判断**：完整回答和预期工具结果返回 Codex。再次请求相同操作前，确认失败尝试是否已经产生部分文件变更。

### 网页已有回答，但 Codex 报告 `browser_stream_inconsistent`

**检查**：最终网页结构无法与已读取的回答可靠对齐。这是回答提取失败，不能仅凭此认定网络断开。原生工具模式会先缓存原始正文，完成后再解析并校验工具调用，因此该错误不意味着 Codex 已经收到报告。

**恢复机制**：普通布局包装会归一为语义段。对于尚未外发的原生工具正文，只有同一回答已完成、快照稳定，且完整保留已有 Markdown（含待提交尾段）及其顺序时，才允许替换内部缓存。不会因此重发提示词或再次执行工具。内容缺失、链接变化、顺序不明或已外发文字被修改时，仍会安全停止。

普通完成路径也会检查待提交段是否仍被覆盖。尾段暂时消失时，在看到完成迹象后最多重新观察5秒；仍无法确认覆盖就报告失败，不返回截断回答，也不拼入过期尾段。

ChatGPT重建节点时，待提交的加粗、斜体或行内代码文字可能继续增长。覆盖校验会区分序列化器生成的Markdown结束标记与实际文字，使未写完的格式化标签可变为完整标签，不被误判丢段。这仅适用于尚未交付的内容；实际文字缺失、链接目标变化和已提交段被修改仍会报错。

未写完的下划线或列表标记也可能让待提交段落临时变为标题，再恢复为段落；行内代码的结束反引号出现时，Windows 路径的 Markdown 转义形式也可能变化。此类比较会统一内容表示，同时保留实际文字、链接和段落顺序；交付采用最终观察到的格式。这不会跳过内容缺失检查，也不会替换 Codex 的压缩摘要。

**处理**：对此错误，自带浏览器会将失败页只读保留最多10分钟；可手动关闭，空间不足时可能提前回收。点击**复制回答**可复制最后一条可见助手回答的未经验证纯文本，请核对后使用；不会自动写回 Codex。失败页不占执行名额，不具备续轮资格；取消和其他错误仍正常释放页面。页面已关闭时，错误提示不保证能恢复内容。重试前导出诊断：`browser.markdown_conflict` 记录不含正文的分段／覆盖及交付元数据；`browser.markdown_rebuilt` 记录成功的内部缓冲恢复。确认 Codex 完整收到一次回答，且没有缺段或重复段落。

### 原生任务取消后浏览器仍被占用

核对准确的原生线程／回合与 Interrupt 钩子结果。网页队列为空不能证明 Codex 已停止执行工具。helper 结束后，取消仅释放该响应拥有的保留页；压缩或历史变更也会在下个会话启动前释放旧页。延迟到达的旧取消不会关闭同一页面的新拥有者。

Windows 配置使用显式处理引号的命令和共享的轻量中断入口，避免完整 CLI 启动耗尽 Codex 原生三秒钩子期限。已有安装需要重新应用连接配置并重启对应 Codex，加载更新的钩子。保留失败或超时钩子证据，不要强制解锁其他任务页面。

### Web 压缩报告 `context_length_exceeded`

**检查**：完整压缩输入超过浏览器内联传输预算。Web2Harness 保留原始上下文并返回不可自动重试的错误；同一请求重连时重放该错误，不再次提交到网页。

**处理**：对支持的模型显式开启 **Context as File（上下文文件）**，或通过 Codex 减少上下文后重试。Web2Harness 不会自动启用文件传输或裁剪历史以适应限制。确认压缩完成且任务继续后，才能判定问题已解决。

### 原生模型压缩返回 `404 Not Found`

**检查**：确认所选模型、实际路由及 `[features].remote_compaction_v2` 设置。原生上游压缩故障与 Web 上下文长度限制属于不同问题。`native_compaction_upstream_failed` 诊断包含路由、模型、HTTP 状态及可用请求标识。

**处理**：保留诊断，先确定设置归哪个应用管理，再考虑修改。Web2Harness 有意管理 `remote_compaction_v2 = false` 以约束保留的 Web 图片历史，不应将翻转这一受管理设置作为通用修复。冲突或遗留的外部覆盖应通过对应路由管理方排查。不要重复创建配置表，也不要为 DEV 测试修改生产设置。

**恢复判断**：原生压缩通过预期路由完成，任务保留上下文继续。如果仍失败，报告实际设置、模型、失败时间和安全日志。扩大 Web 预算或反复应用配置不能证明原生压缩已修复。

### 旧图片再次出现，或附件不完整

**检查与处理**：Codex 会话上下文包含之前的任务图片，桥接保留全部图片，单次提交超过十张会明确报告限制。同一任务再次附加属于预期行为；如需排除，应新建任务。附件未完整接收或出现其他 Codex 任务的图片时，保留失败追踪并标明附件阶段。

不要将内联图片替换为任意本地文件路径；仅模型和压缩轮次不会因此获得不受限文件访问。

**恢复判断**：正确任务接收到预期图片，新任务不携带上一任务的图片上下文。

### 浏览器图片生成始终没有返回图片

**检查与处理**：ChatGPT 内部图片生成不是受支持的 Web 轮次，其生命周期不同于文本回答。可用时使用 Codex 原生 Image Gen 工具；其 `/v1/images/generations` 和 `/v1/images/edits` 请求携带 Codex 认证转发到原生后端。单独诊断该路径的原生认证、额度和上游问题。

**恢复判断**：原生图片工具返回真实图片结果。ChatGPT 连接器不提供原生图片凭据或额外额度。

## 收集支持报告

诊断包默认包含全部保留的相关记录，可按最近24小时或自定义日期时间缩小范围；与日志页面筛选无关。先读 `summary.txt`，再按请求/会话标识查看 `timeline.jsonl`；`snapshot.json` 反映导出时状态，`manifest.json` 说明覆盖时段及缺失/损坏/截断。包内不包含原始对话、工具输入输出或截图；若证据不够，再有针对性地补充复现信息。

完成一次聚焦复现后，选择**用量与诊断 → 日志 → 导出诊断包**；启动受阻时使用启动诊断导出。分享前检查导出内容和截图，并包含：

- Web2Harness 版本、安装方式、操作系统和架构；
- Codex Desktop 或 CLI 版本，以及常规或 DEV 配置；
- 账号套餐、当前模式、交互方式和准确模型；
- 复现步骤、预期与实际结果、完整最终错误和失败时间；
- 新任务是否复现，以及真实工具是否执行；
- 相关交接、模型切换或压缩细节；
- 紧接该次尝试导出的安全日志。

不要在公开报告中包含原始日志、凭据、API key、Tunnel ID、浏览器状态、私有提示词、敏感工具结果、配置备份或私有绝对路径。截图用于补充错误和日志，通常不能单独确定失败层面。疑似漏洞遵循[私密漏洞报告流程](release.zh-CN.md#vulnerability-reporting)。
